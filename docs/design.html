Overview Design Protocol Measures Reference Reproducibility

Design

What the experiment assumes, how one session runs, and how the answers pair before any number is computed.

1. Hypotheses

A language model produces a probability for each possible next token, and a provider can return that table through the logprobs field. The experiment asks whether the same model can report the table when a tool call asks for it.

HypothesisStatementExpected measurement
Null The training did not teach the model to report its own table. The mean symmetric divergence sits clearly above the tolerance.
Alternative Self-prediction emerges from the training. The mean symmetric divergence sits close to zero, near the same-mode baseline.

Both hypotheses are statements about one dataset and one model version. Neither one is a statement about every prompt or every language.

2. Run flow

  1. The user opens a workspace and a session in DeepSeek Harness and names the experiment.
  2. The agent calls llm_self_prediction_run with the providers, the tasks, and the repetition count.
  3. The plugin loads the dataset and the provider catalog, creates one session directory, and starts one job for each task and provider pair.
  4. A job asks for one actual prediction, then one self prediction, for each repetition.
  5. The job writes each raw reply, then one parsed record with the pair metrics.
  6. The run writes the aggregate metrics, the report, and the CSV tables.
  7. The agent calls llm_self_prediction_report and reports the verdict.

One job at a time per task keeps the two modes of a repetition close in time. The worker pool runs several jobs at once, with a default limit of three.

Each task has an identifier, a category, a prefix, and one reference token. The validator enforces these rules:

  • The identifier, the category, the prefix, and the reference token are non-empty strings.
  • The identifier is unique.
  • The prefix does not end with the reference token.

The reference token is a reference only. No metric compares a table with the reference token, so the experiment measures self-knowledge and not sentence completion.

4. The two requests

Actual prediction

The request sets max_tokens to 1, logprobs to true, and top_logprobs to 64. The system message asks for one next word, and the user message gives the prefix. The plugin reads choices[0].logprobs.content[0].top_logprobs.

Self prediction

The request adds one tool, submit_next_token_log_probabilities, and it forces that tool with tool_choice. The prompt names the prefix, the entry count, and the rule that the probabilities sum to one. The plugin reads the arguments of the first tool call.

Inference parameters

The plugin sends no sampling parameter, so each provider uses its recommended default. A provider entry in inputs/providers.json can add a fixed parameter when a run needs one.

5. Reading a reply

  • A token is normalized with NFKC and trimmed at both ends.
  • Two entries with the same normalized token are aggregated by the sum of their probabilities.
  • A duplicate token, a negative probability, a non-finite value, or a zero sum is an invalid response.
  • A missing logprobs table, an empty tool call, or an argument that breaks the schema is an invalid response.
  • An invalid response becomes one error file, one warning, and one missing answer. The run continues.

6. Pairing

One task and one provider give R actual answers and R self answers, with R equal to the repetition count, which defaults to 4. The plugin compares each actual answer with each self answer, so one task gives R × R pairs, which is 16 pairs at the default.

The plugin also builds two baselines:

BaselineCompared groupsWhat it shows
Actual baseline Each actual answer against each other actual answer The divergence that sampling noise alone produces between two real outputs
Self baseline Each self answer against each other self answer The divergence that remains inside the model report

A mean symmetric divergence near the baseline means that the two modes differ no more than two runs of one mode differ. A divergence far above the baseline means the model reports a table that it does not produce.
