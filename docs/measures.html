Measures

How two top-64 tables become one divergence, one interval, and one verdict.

1. Normalize one table

  1. Normalize each token with NFKC and trim it.
  2. Aggregate two entries with the same token by the sum of their probabilities.
  3. Convert each natural-log probability with p = exp(logProbability).
  4. Sort the entries from the highest probability to the lowest.

A table with a non-finite value, a negative probability, or a zero total is invalid, and the answer is missing.

2. Align two tables

Two top-64 tables rarely share the same tokens, because the tail differs. The plugin builds the union of both supports, gives the probability floor 1e-12 to each token that one side does not report, and renormalizes each side over the union.

tokens = union(actual.tokens, self.tokens)
p_i = actual.probability(token_i) or 1e-12
q_i = self.probability(token_i) or 1e-12
p_i = p_i / sum(p),  q_i = q_i / sum(q)

The floor keeps a divergence finite when one table gives zero probability to a token that the other table reports. The floor is the reason a missing tail cannot become an infinite divergence.

3. Measures of one pair

MeasureDefinitionRangeReading
KL(P||Q) Σ pi ln(pi / qi) 0 to ∞ The extra cost of coding an actual table with a self table.
KL(Q||P) Σ qi ln(qi / pi) 0 to ∞ The extra cost in the other direction. It is not equal to the first value.
Symmetric KL ( KL(P||Q) + KL(Q||P) ) / 2 0 to ∞ The reported distance, in nats.
JS ½ KL(P||M) + ½ KL(Q||M), with M = (P + Q) / 2 0 to ln 2 A bounded distance that a reader can compare across tasks.
TV ½ Σ |pi − qi| 0 to 1 The largest probability difference that the two tables give one event set.
Top-1 The most likely token of each table true or false Whether the model at least names its own first choice.
Coverage The probability that one table gives to the support of the other 0 to 1 Whether the model reports the tokens that the provider weighs.
Union support size The count of aligned tokens 1 to 128 How much the two supports differ.

4. Aggregate one provider

The plugin collects the pair values of every task and reports the mean, the median, and the count. It also reports the two baselines: actual against actual, and self against self.

mean symmetric KL = mean(pair.symmetricKl for each task and each pair)
baseline         = mean(symmetric KL between two answers of the same mode)

5. Confidence interval

The interval comes from a percentile bootstrap of the mean symmetric divergence:

  1. Draw 2000 resamples of the pair values with replacement, using a fixed seed.
  2. Compute the mean of each resample.
  3. Take the 2.5 percent and 97.5 percent quantiles.

The fixed seed makes the interval reproducible. The same pair values and the same seed give the same interval on every platform.

6. Verdict

VerdictConditionReading
separated lower bound > tolerance The self table differs from the actual table by more than the tolerance. The null hypothesis holds for this sample.
indistinguishable upper bound < tolerance The two tables agree within the tolerance. The alternative hypothesis holds for this sample.
inconclusive the interval crosses the tolerance The sample cannot decide. The run needs more pairs, or a smaller tolerance.

The default tolerance is 0.05 nats. A run can set another value, and the report records the value that the run used.

7. Reading the baseline

  • A mean divergence close to the same-mode baseline means the two modes differ no more than two runs of one mode differ.
  • A mean divergence far above the baseline means the model reports a table that it does not produce.
  • A baseline that is itself large means the provider samples widely, and the run needs more repetitions before it can decide.
