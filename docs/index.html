Does a model know its own next token?

A DeepSeek Harness plugin that measures how far the next-token table of a language model stands from the table that the same model reports about itself.

The question. A model reads a sentence prefix. The provider reports the top 20 next-token choices. Does the model know that table? The plugin asks the model to write the table, compares the two tables, and repeats the comparison under two injections.

Dataset
32 Simplified Chinese and 32 US English tasks in 8 categories in inputs/testing-dataset/
Providers
Hugging Face router models, OpenAI chat models, and a deterministic mock provider
Conditions
actual, self, actual then actual, and actual then self; 8 repetitions each
Comparisons
3: self, actual then self, and actual then actual against the actual table
Verdict
Bootstrap interval of the mean symmetric KL against a tolerance of 0.05 nats
Hypothesis test
One-sided Wilcoxon signed-rank test of the median divergence, alpha 0.05

Why four conditions

  • The actual table is the ground truth, because the provider computes it and the model does not write it.
  • The self table shows what the model says when it must state its own prediction.
  • The actual-then-self table shows whether the true table moves the self report toward the truth.
  • The actual-then-actual table is the control. The model reads the table, reads the table again, and any divergence is the noise of the reading, not a self report.

What one run writes

  • outputs/<xid>/intermediate/ holds every raw exchange, one file for each call.
  • outputs/<xid>/results/ holds the metrics, the records, the report, and the tables.
  • outputs/<xid>/demos/ holds the static bilingual demonstration website.
  • outputs/<xid>/revision.json holds one entry for each revise pass of the folder.
  • node lib/cli.js demos [<xid>] writes that website again from the current templates.

One folder for one run

  • A run reads one output folder and writes only that folder.
  • A run that names an existing folder revises it. The pass keeps every raw table that the current protocol reads, requests the absent tables, and removes each raw file that the current protocol does not read.
  • node lib/cli.js rename --session=<xid> moves the folder to a fresh identifier, and the manifest keeps the old identifier.

Install and first run

# register the package directory as a bundle
plugin_manager install_bundle target=<absolute path of this package>

# a dry run needs no credential and no network
node lib/cli.js run --dry-run --tasks=Z001,E001 --repetitions=1

# a real run reads the key from .env
node lib/cli.js env
node lib/cli.js run --folder=<name> --repetitions=8

# a revise pass of the same folder, then a new identifier
node lib/cli.js run --folder=<name> --repetitions=8
node lib/cli.js rename --session=<name>
