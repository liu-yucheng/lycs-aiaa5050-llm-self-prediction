Does a model know its own next token?

A DeepSeek Harness plugin that measures the distance between the next-token distribution that a language model actually produces and the distribution that the same model reports through a tool call.

The two questions. For one sentence prefix, the plugin asks the model for the top 20 next-token log probabilities, then asks the model to report that same table itself. The divergence between the two tables is the measurement.

Dataset
64 Simplified Chinese and 64 US English tasks in 8 categories, dataset llm-self-prediction-zh64-en64-v2
Providers
DeepSeek, Qwen, GLM flash models, plus a deterministic mock provider
Table size
20 entries for the actual request, at most 64 entries for the self request
Pairs
4 actual answers × 4 self answers = 16 pairs for each task and provider
Verdict
Bootstrap interval of the mean symmetric KL against a tolerance of 0.05 nats

Why the comparison is fair

A raw divergence mixes two causes: the model reports a different table, or the model samples a different token. The run separates them.

  • Each task gives four actual answers and four self answers, so sampling noise appears in both groups.
  • Two same-mode baselines compare actual with actual and self with self, and they show the noise floor of the provider.
  • A bootstrap interval states how much of the difference the sample size supports.
  • The plugin never uses the reference token of the dataset in the metric, so a wrong sentence completion cannot flatter or spoil a divergence.

Install and first run

# register the package directory as a bundle
plugin_manager install_bundle target=<absolute path of this package>

# in a DeepSeek Harness session, ask the agent:
use lycs-aiaa5050-llm-self-prediction to run an experiment

A dry run needs no credential and no network.

node lib/cli.js run --dry-run --limit=3 --repetitions=2

A real run needs an API key. The workspace holds two directories: inputs/ for the private file .env, the example file, and optional replacements of the dataset and the provider catalog, and outputs/ for one directory of each session. The first run copies the public example file to inputs/.env and stops with a prompt that names the keys to fill in. The command below shows the path and the state of each key:

node lib/cli.js env
