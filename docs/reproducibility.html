Reproducibility

What a session records, which rules the plugin never bends, and what one run can and cannot claim.

1. Recorded fields

session.json holds these fields, so a reader can rebuild the run without asking the person who started it.

FieldContent
sessionCodeThe UTC time, the seed, and six hex characters.
datasetId, datasetHash The dataset name and the SHA-256 digest of the dataset content.
options The providers, the tasks, the limit, the repetitions, the tolerance, the seed, the concurrency, and the dry-run flag.
providers Each provider key, label, base URL, model name, and credential variable. The credential itself is absent.
environment The Node.js version, the platform, the plugin name and version, the seed, the start time, the end time, the elapsed seconds, the path of the environment file, and whether the run created that file.
status running, complete, or failed, with the failure message.

The model name and the base URL identify the model version that the provider served at the run time. The provider does not always publish a separate version string, so the date of the run is part of the record.

2. Integrity rules

  • Every raw reply is stored before parsing, and no run rewrites an existing raw file.
  • The dataset and the provider catalog are inputs. A run reads them and never writes to them.
  • The report only states a number that metrics.json holds.
  • A tolerance, a repetition count, or a seed is recorded with the verdict, because each one changes the verdict.
  • A failed call stays visible as an error file. A run does not drop a failure from the count.
  • The metric never uses the reference token, so a wrong completion cannot improve or spoil a divergence.

3. Reproducing a run

  1. Read session.json and copy the provider list, the task list, the repetitions, the tolerance, and the seed.
  2. Fill in the same API keys in the private environment file.
  3. Run node lib/cli.js run with those values.

A provider with a live model may serve another model version later, and a sampling parameter may change. The plugin cannot fix that. The record of the model name, the base URL, and the run date is the evidence of the version that the run used.

A dry run is fully reproducible: the mock provider derives each table from a SHA-256 hash of the prefix and the token, so the same seed and the same task give the same numbers.

5. Limitations

  • One run covers at most 128 tasks in two languages. A verdict describes this dataset and this model version.
  • A top-20 table holds most of the probability mass of a typical next-token distribution. The floor of 1e-12 keeps a divergence finite, and it slightly changes a value when a tail is missing.
  • The self request depends on a tool call. A provider that ignores a forced tool call gives an invalid response, not a measurement.
  • The same-mode baseline measures sampling noise, and it cannot separate a stable bias from noise when the repetition count is small.
  • The plugin sends temperature=0 on every request, so a provider that ignores a zero temperature can still sample a different token. The plugin sends no top-p value.
